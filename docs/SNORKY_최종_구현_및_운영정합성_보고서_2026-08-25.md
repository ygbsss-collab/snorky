## 2. DB 스키마 및 무결성 제약조건

- **테이블명**: `public.point_evaluation_results`
- **고유키 제약조건**: `UNIQUE(point_id, target_date, mode, period_start, period_end)`
- **모드 제약조건**: `CHECK (mode IN ('TODAY', 'TODAY_HOURLY', 'SHORT', 'MID'))`
- **품질/안전 제약조건**:
  - `quality_status`: `'READY'`, `'PARTIAL'`, `'UNKNOWN'`
  - `safety_status`: `'PASS'`, `'BLOCK'`, `'UNKNOWN'`
- **점수 규칙**:
  - `condition_score`: 0 ~ 100 정수 (BLOCK / UNKNOWN 시 `null`로 저장)
  - `recommendation`: '추천' / '주의' / '비추천'

## 3. 프론트엔드 전환 원칙 (Zero Client Math)

1. **클라이언트 재계산 100% 제거**: 브라우저에서 `SNORKYEval`을 직접 호출하여 실시간으로 기상/해양 물리 수식이나 점수를 계산하지 않습니다.
2. **단일 Result Object 소비**: 모든 화면(Home, Today, SHORT, MID, BEST, Scrubber Modal)은 `SNORKYEvaluationResults` 공통 어댑터를 통해 Supabase `point_evaluation_results`에 선계산되어 저장된 행만 읽어와 표시합니다.
3. **결측 및 실패 처리**:
   - 데이터 미준비 또는 조회 실패 시 임의 가상값 생성 및 클라이언트 폴백 재계산 금지.
   - 화면에 `--` 및 `확인 필요`를 명확히 렌더링하고, BEST 추천 목록에서 자동 제외.
4. **BEST 후보 선정 규칙**:
   - `safety_status === 'PASS'` AND `condition_score !== null` (BLOCK/UNKNOWN/null 완벽 배제).
   - `condition_score` 내림차순 정렬.
