V1.2의 Base 계산 구조, V1.3의 Final Visual Visibility, V1.4의 풍향·파주기·수온 활동 적합도 규칙을 보존하면서 Today / +1~+3일 / +4~+6일의 6일 예보 평가 구간과 중기 Marine 전용 계산 계약을 추가한다. 현재 SNORKY가 실제로 구현·보유하는 데이터만 알고리즘 입력으로 사용한다. 데이터가 없는 항목을 임의 추정하거나 가상 변수로 생성하지 않는다. Safety 판단은 점수와 분리하며 Hard Safety 발효 시 점수를 표시하지 않는다. 현재 바다 상태와 과거 파도·강수 이력을 분리하여 수중시야 회복 지연을 반영한다. 포인트별 Environment Profile을 사용하여 같은 해상조건에서도 포인트별 차이가 발생하도록 한다. Safety / Recommendation / Condition Score를 서로 다른 의미의 결과로 분리한다. 야간·해질녘은 바다 자체 점수를 왜곡하지 않고 활동 추천만 제한한다. 2. 현재 사용 가능한 입력 데이터 구분 사용 데이터 용도 해양 유의파고, 파주기, 파향, 유속, 수온 Wave, Current, Visibility, Comfort 기상 풍속, 풍향, 강수량, 강수확률, 구름/하늘상태, 기온 Wind, Visibility, Comfort 안전 KMA 해상특보 및 기존 Hard Safety 입력 Safety Gate 시간 일출, 일몰, 현재/예보 시각 Activity Time Gate 포인트 환경 terrain, exposure, breakwaterShelter, eastWindSensitivity, swellSensitivity 포인트별 보정 V1.4 추가 입력: 일반 windExposureDirection은 실제 값이 존재할 때 풍향 상대각 계산에 사용한다. 값이 없으면 방향 효과를 중립값으로 처리하며 임의 생성하지 않는다. 하천거리, 우수관거리, 입자크기, 해저경사, 기압변화율, 실제 이안류 여부 등 현재 확정되지 않은 값은 계산에 사용하지 않는다. 3. 전체 알고리즘 파이프라인 DATA QUALITY GATE: 필수 안전 데이터 존재 여부 확인 SAFETY GATE: KMA 특보 + Hard Safety 판정 WAVE ENGINE: 파고 기본점수 + 파주기 × swellSensitivity 손실 보정 + 파향·포인트 환경 보정 CURRENT ENGINE: 유속 기반 보수적 위험 평가 WIND ENGINE: 풍속 기본점수 + 풍향 상대각 × windSensitivity 손실 보정 ENTRY CONDITION A: Wave / Current / Wind의 비선형 결합 VISIBILITY B: 현재·과거 파도 및 강수 이력 + 포인트 지형 기반 회복 지연 COMFORT C: V1.2의 현재 강수·기온·구름 기반 체감환경. 수온은 V1.4 활동 적합도 계층으로 분리한다. Comfort C 및 Final Condition Comfort는 V1.2의 현재 강수량, 기온, 구름량을 사용하며 바다 자체가 좋은데 흐리다는 이유로 점수가 크게 낮아지지 않도록 한다. 수온은 V1.4에서 별도 숫자 점수를 만들지 않고 활동 적합도와 Recommendation Cap에만 사용한다. Comfort Modifier:  CM = 0.95 + 0.05 × (C/100) Core:  Core = 100 × (A/100)^0.63 × (B/100)^0.37 Final:  Final Score = Core × CM Comfort는 Core 바다점수를 최대 약 5%만 감점하며, 좋은 날씨라고 Core 점수를 추가 상향하지 않는다. 11. Base Visibility B와 Final Visual Visibility Base Visibility B: 물 자체의 예상 투명도와 교란 후 회복 상태를 나타내는 0~100 점수다. 자연광 시간대 때문에 이 값을 직접 변경하지 않는다. Final Visual Visibility: 해당 3시간 예보 슬롯에서 사람이 실제로 물속을 볼 수 있는 정도를 나타내는 사용자 표시용 0~100 점수다. DAY, SUNRISE_EFFECT, SUNSET_EFFECT 계산식: Final Visual Visibility = clamp(Base Visibility B - Visual Condition Penalty, 0, 100) NIGHT 계산식: Final Visual Visibility = 0. Base Visibility B는 그대로 보존한다. 20. 3시간 예보 기준 자연광 슬롯 결정 모든 판정은 현재 시스템 시각이 아니라 해당 row의 evaluatedAt(선택된 예보 슬롯의 날짜·시각)과 그 날짜·포인트의 일출·일몰 시각을 사용한다. V1.4 풍향 × 풍향 민감도 보정 풍향은 Base Wind Score에 별도 고정점수를 더하거나 빼지 않는다. 풍속에서 이미 발생한 손실에 포인트 기준 상대풍향과 windSensitivity를 적용한다. windLoss = 100 - baseWindScore effectiveDirectionFactor = 1 + (directionFactor - 1) × windSensitivityFactor adjustedWindLoss = windLoss × effectiveDirectionFactor finalWindScore = clamp(100 - adjustedWindLoss, 0, 100) 상대각 directionFactor 의미 0° 1.20 정면 Onshore 45° 1.10 사선 Onshore 90° 1.00 Cross-shore 135° 0.95 사선 Offshore 180° 0.90 정면 Offshore 중간 상대각은 인접 기준점 사이에서 선형 보간한다. 상대각은 0~180°로 정규화하며, 0°는 바다에서 포인트 방향으로 부는 정면 Onshore, 180°는 육지에서 바다 방향으로 부는 정면 Offshore로 정의한다. 기상 풍향과 windExposureDirection은 모두 ‘바람이 불어오는 방향’ 기준으로 통일한다. windSensitivity 계수 low 0.75 medium 1.00 high 1.25 풍속 ≤ 3m/s: 방향 계산을 건너뛰고 Wind Score 100을 유지한다. 풍향 또는 windExposureDirection 누락: effectiveDirectionFactor = 1. 민감도 누락 또는 알 수 없는 값: medium = 1.00. Cross-shore는 민감도와 관계없이 Base Wind Score를 유지한다. Offshore는 고정 보너스가 아니라 기존 손실만 완화한다. Hard Safety는 원천 풍속·특보로 별도 판정하며 풍향 보정으로 완화하지 않는다. 29. Safety와 Worst Gate는 활동구간의 모든 원본 시간별 값을 검사하며, 급격한 위험값을 평균·보간·smoothing으로 완화하지 않는다. 40. +4~+6일 Condition Score - 중기 알고리즘 3차 채택안 40.1 Wave Score 활동구간 평균 유의파고를 기존 V1.2 파고 점수표에 적용한다. 중간값은 기존 방식대로 보간한다. 파주기는 기존 Wave Engine의 파고 손실 보정 역할만 재사용하며 독립 점수나 신규 고정감점을 만들지 않는다. +4~+6일에는 파향 보정을 적용하지 않는다. 40.2 Current Score 활동구간 평균 해류속도를 기존 V1.2 유속 점수표에 적용한다. 중간값과 단위 Normalize도 기존 규칙을 재사용한다. 40.3 Mid Entry Wind는 +4~+6일 Mid Entry에서 제외한다. 기존 Today Entry의 Wave:Current 비율 60:30을 2:1로 정규화해 기하결합과 기존 weakest-link Gate를 유지한다. A₀(mid) = 100 × (Wave/100)^(2/3) × (Current/100)^(1/3) M = min(Wave, Current) G = 0.70 + 0.30 × (M/100) Mid Entry = A₀(mid) × G 수온은 원값과 구간 평균·범위를 표시하되 신규 점수표를 만들지 않고 Condition 숫자에 직접 가중하지 않는다. V1.4의 수온 활동 적합도/Recommendation Cap이 적용 가능한 입력 품질을 갖춘 경우에도 Condition 숫자와는 분리한다. 41. +4~+6일 예상 수중시야 - MID_MARINE_ONLY +4~+6일 Visibility는 기존 V1.2 Marine History 구조를 재사용한다. 유의파고·파주기 이력, Environment Profile 및 최대 약 48시간 Exponential Decay를 사용하되 실제 강수량 입력을 제거한다. 내부 모드는 MID_MARINE_ONLY로 구분한다. 실제 강수량이 중기 구간에 제공되지 않으므로 Visibility 입력에서 제외한다. 강수확률을 강수량으로 변환하거나 대체값으로 사용하지 않는다. 강수확률을 Visibility의 직접·간접 입력, 감점 또는 탁도 추정값으로 사용하지 않는다. 이력 부족 시 사용 가능한 Marine 이력만 사용하고 데이터 부족 상태를 표시한다. 누락 강수를 0mm 또는 좋은 조건으로 간주하지 않는다. KMA 공식 오전/오후 날씨는 표시·설명에 사용할 수 있으나 MID_MARINE_ONLY Base Visibility 계산에는 투입하지 않는다. 42. 서버 선계산·Cache 및 Result Object 계약 +4~+6일 계산은 프론트엔드가 화면 로딩 시 실시간 수행하지 않는다. 서버/API의 Cache refresh 단계에서 선계산하고 Evaluation Cache에 저장하며, 앱은 저장된 결과만 소비한다. 예보 및 Marine 원천값 수집·Normalize 활동구간 집계와 원본 Worst 검사 Condition, Visibility 및 설명 필드 계산 공통 Result Object를 Evaluation Cache에 저장 앱은 캐시 결과를 표시하고 화면별 재계산을 금지 Result Object는 기존 공통 필드를 유지하고 forecastRange, period(AM/PM), evaluationMode, sourceWindow, representativeValues, displayRanges, worstGate 및 dataQuality를 구분해 저장한다. 값이 없으면 0·평균·최상값으로 채우지 않는다. 43.
