정합성 체크리스트 - 2026-08-24 14-05
현재까지 확인된 사실, 기준서 오류 정정, 실제 코드 충돌, 남은 검증을 한 문서에 통합
0. 최상위 검증 원칙
목적은 코드를 기준서에 맞추는 것이 아니라, 실제 코드·DB·API 동작과 알고리즘 기준서·API 기준서를 상호 검증해 최종 정합성을 만드는 것이다.
기준서가 틀렸으면 기준서를 수정한다. API 기준서가 틀렸으면 API 기준서를 수정한다. 실제 코드가 레거시·중복·오류면 코드를 수정한다.
체크리스트는 기준이 아니라 검증 기록이다. 이전 결론이 새 실증과 충돌하면 이전 결론을 정정한다.
없는 값·수식·임계값·상태코드를 만들지 않는다. 근거가 부족하면 [확인 필요]로 둔다.
같은 의미의 데이터는 한 경로만 유지하고, 실제 소비처가 없는 필드는 수집·정규화·캐시·응답에서 제거한다.
IDE·코덱스 명령은 최소 토큰으로 작성하고, 같이 검증 가능한 항목은 한 번에 묶는다.
