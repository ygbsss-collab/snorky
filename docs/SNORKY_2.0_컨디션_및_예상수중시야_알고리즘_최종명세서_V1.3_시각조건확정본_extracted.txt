SNORKY 2.0 컨디션 및 예상 수중시야 알고리즘 최종 명세서 V1.3 스노클링 · 레크리에이션 프리다이빙 포인트 추천용 확정일: 2026-08-21 문서 성격: SNORKY 2.0 구현 기준 최종 설계 명세 1. 문서 목적 및 최종 설계 원칙 본 문서는 SNORKY 2.0에서 사용할 ‘포인트 컨디션’과 ‘예상 수중시야’ 알고리즘의 최종 V1.3 설계를 정의한다. 목표는 초보자를 포함한 스노클링·레크리에이션 프리다이빙 사용자가 전문적인 해양·기상 수치를 직접 해석하지 않아도 특정 포인트의 현재·시간별 상태를 이해하고 방문 및 입수 시점을 판단할 수 있도록 하는 것이다. 현재 SNORKY가 실제로 구현·보유하는 데이터만 알고리즘 입력으로 사용한다. 데이터가 없는 항목을 임의 추정하거나 가상 변수로 생성하지 않는다. Safety 판단은 점수와 분리하며 Hard Safety 발효 시 점수를 표시하지 않는다. 현재 바다 상태와 과거 파도·강수 이력을 분리하여 수중시야 회복 지연을 반영한다. 포인트별 Environment Profile을 사용하여 같은 해상조건에서도 포인트별 차이가 발생하도록 한다. Safety / Recommendation / Condition Score를 서로 다른 의미의 결과로 분리한다. 야간·해질녘은 Base Visibility B와 바다 자체 점수를 왜곡하지 않는다. 자연광에 따른 실제 시야는 Final Visual Visibility로 분리하고, 활동 추천은 Activity Time Gate에서 제한한다. 1.1 V1.3 주요 변경 Base Visibility B와 Final Visual Visibility를 분리한다. 자연광과 기상상태를 결합한 사람 눈 기준 Visual Condition 보정을 추가한다. 3시간 예보 슬롯 기준 일출·일몰 대표 슬롯을 정의한다. NIGHT의 Final Visual Visibility를 0점으로 확정한다. Final Visual Visibility 전용 등급 라벨을 정의한다. Activity Time Gate와 Visual Visibility의 역할을 분리한다. V1.2의 Wave, Current, Wind, Entry A, Base Visibility B, Comfort C, Final Condition 및 Safety 구조는 보존한다. 2. 현재 사용 가능한 입력 데이터 구분 사용 데이터 용도 해양 유의파고, 파주기, 파향, 유속, 수온 Wave, Current, Visibility, Comfort 기상 풍속, 풍향, 강수량, 강수확률, 구름/하늘상태, 기온 Wind, Visibility, Comfort 안전 KMA 해상특보 및 기존 Hard Safety 입력 Safety Gate 시간 일출, 일몰, 현재/예보 시각 Activity Time Gate 포인트 환경 terrain, exposure, breakwaterShelter, eastWindSensitivity, swellSensitivity 포인트별 보정 V1.3에서 사용하지 않는 값: 일반 windExposureDirection, 하천거리, 우수관거리, 입자크기, 해저경사, 기압변화율, 실제 이안류 여부 등. 이 값들은 현재 SNORKY의 확정 입력 데이터가 아니므로 계산에 사용하지 않는다. 3. 전체 알고리즘 파이프라인 DATA QUALITY GATE: 필수 안전 데이터 존재 여부 확인 SAFETY GATE: KMA 특보 + Hard Safety 판정 WAVE ENGINE: 파고 + 파주기 + 파향 + 포인트 환경 보정 CURRENT ENGINE: 유속 기반 보수적 위험 평가 WIND ENGINE: 풍속·풍향 + 현재 eastWindSensitivity 활용 ENTRY CONDITION A: Wave / Current / Wind의 비선형 결합 BASE VISIBILITY B: 현재·과거 파도 및 강수 이력 + 포인트 지형 기반 물 자체의 수중시야 COMFORT C: 현재 강수·기온·수온·구름 기반 체감환경 FINAL CONDITION: A와 B 중심 Core Score + C의 소폭 감점 Modifier ACTIVITY TIME GATE: 일출·일몰 기준 야간/해질녘 추천 제한 OUTPUT: Safety / Recommendation / Condition Score / 상세 설명 4. Entry Condition A 기본 Entry:  A₀ = 100 × (Wave/100)^0.60 × (Current/100)^0.30 × (Wind/100)^0.10 기하결합을 사용하여 한 요소가 매우 나쁠 때 다른 좋은 요소가 위험을 과도하게 상쇄하는 문제를 줄인다. M:  M = min(Wave, Current) Gate:  G = 0.70 + 0.30 × (M/100) 최종 Entry:  A = A₀ × G Wave 또는 Current가 매우 낮을 때 Entry를 연속적으로 추가 감점하며, 계단식 Cap으로 인한 점수 급변을 피한다. Entry A 기본 추천 해석 80~100 추천 65~79 주의 0~64 비추천 9. Base Visibility B — 물 자체의 수중시야 수중시야는 현재 파고만으로 계산하지 않는다. 현재 바다가 잔잔해도 이전에 높은 파도나 강수가 있었다면 물속 상태가 즉시 회복되지 않는다는 원칙을 적용해 과거 이력을 누적한다. 현재 및 과거 파고 과거 파주기(데이터가 존재하는 범위) 현재 및 과거 강수량 terrain, exposure, breakwaterShelter, swellSensitivity 0~6h 60%, 6~12h 25%, 12~24h 15% 고정 구간 방식은 사용하지 않는다. 최대 약 48시간의 이력을 보관하고 시간이 지날수록 영향이 자연스럽게 감소하는 Exponential Decay를 적용한다. 일반 감쇠:  Impact(t) = Impact₀ × exp(-λ × t) λ와 반감기는 실제 운영 결과에 따라 튜닝한다. 요소 역할 exposure 과거 파도가 포인트를 얼마나 강하게 교란했는지 보정 breakwaterShelter 차폐가 높을수록 파도 교란량 감소 swellSensitivity 장주기 파도 시 교란 영향 추가 보정 terrain 교란 후 수중시야 회복속도 결정 terrain은 현재 수중시야를 직접 정하는 값이 아니라 회복속도를 조정하는 값이다. 암반은 빠른 회복, 일반/혼합은 중간, 모래는 느린 회복을 기본 방향으로 둔다. 강수는 역할을 분리한다. 과거·누적 강수는 물의 탁도 변화로서 Base Visibility B에 반영하고, 현재 비는 자연광 저하와 사람 눈의 시각조건 악화로서 Visual Condition에 반영한다. 동일 강수 영향을 두 단계에 중복 계산하지 않으며, 강수확률은 주요 점수 입력으로 사용하지 않는다. B 점수 예상 수중시야 상태 사용자 표현 85~100 좋음 수중시야 좋은 상태로 예상 65~84 양호 대체로 양호 45~64 보통 / 회복 중 최근 파도·강수 영향이 일부 남음 25~44 나쁨 탁도 영향이 큰 상태로 예상 0~24 매우 나쁨 수중시야가 매우 제한될 가능성 9.1 Base Visibility B 정의 Base Visibility B는 파도, 너울, 파주기, 현재·과거 강수 이력, terrain, exposure, breakwaterShelter, swellSensitivity 등을 기반으로 계산하는 “물 자체의 수중시야”다. 기존 V1.2 Visibility B 계산 구조와 지수감쇠 이력 모델을 그대로 유지한다. Base Visibility B는 자연광, 일출·일몰 대표 슬롯 또는 NIGHT 때문에 직접 변경하지 않는다. Base Visibility B 점수 등급 85~100 좋음 65~84 양호 45~64 보통 · 회복 중 25~44 나쁨 0~24 매우 나쁨 9.2 Final Visual Visibility 정의 Final Visual Visibility는 사용자에게 최종 표시되는 사람 눈 기준 예상 수중시야다. 물 자체의 투명도와 실제 시간대·기상조건에서 사람이 물속을 볼 수 있는 정도를 분리한다. DAY, SUNRISE_EFFECT, SUNSET_EFFECT에서는 Final Visual Visibility = max(0, Base Visibility B - Visual Condition Penalty)로 계산한다. NIGHT는 감점 방식을 사용하지 않으며 Final Visual Visibility = 0점으로 고정한다. 일반 SNORKY 평가는 랜턴·수중 조명 등 인공조명을 사용하지 않는 상황을 기본 전제로 한다. 9.3 자연광 조건과 3시간 대표 슬롯 자연광 조건 판정 기준 DAY 일출 영향 슬롯 이후부터 일몰 영향 슬롯 이전까지의 낮 슬롯 SUNRISE_EFFECT 실제 일출시각에 가장 가까운 제공 슬롯 SUNSET_EFFECT 실제 일몰시각에 가장 가까운 제공 슬롯 NIGHT 일출 영향 슬롯 이전 및 일몰 영향 슬롯 이후 일출·일몰 영향 슬롯은 천문학적 일출·일몰 시각 자체가 아니다. SNORKY의 3시간 간격 제공 슬롯 중 실제 시각에 가장 가까운 슬롯을 자연광 변화의 대표 슬롯으로 사용한다. 예: 실제 일출 05:00이면 03/06/09 중 06시를 SUNRISE_EFFECT로 사용한다. 실제 일몰 19:00이면 18/21 중 18시를 SUNSET_EFFECT로 사용한다. 9.4 기상상태 및 Visual Condition 감점표 각 자연광 조건에 맑음, 구름많음, 흐림, 비를 결합하여 총 16개 Visual Condition을 사용한다. 기상상태 정의는 SNORKY 시간별 컨디션 기상 아이콘 체계와 동일하게 유지한다. 자연광 조건 맑음 구름많음 흐림 비 DAY 0 -5 -10 -25 SUNRISE_EFFECT -10 -15 -20 -35 SUNSET_EFFECT -10 -15 -20 -35 NIGHT 0점 고정 0점 고정 0점 고정 0점 고정 9.5 강수 이중감점 방지 강수 입력 역할 적용 위치 과거·누적 강수 물의 탁도 변화와 회복 지연 Base Visibility B 현재 비 자연광 저하와 사람 눈의 시각조건 악화 Visual Condition 동일 강수 영향을 Base Visibility B와 Final Visual Visibility에 중복 계산하지 않는다. 9.6 Final Visual Visibility 등급 Final Visual Visibility 점수 등급 85~100 좋음 65~84 양호 45~64 보통 25~44 나쁨 0~24 매우 나쁨 Final Visual Visibility에서는 “회복 중” 표현을 사용하지 않는다. “보통 · 회복 중”은 Base Visibility B 전용 라벨로 유지한다. 9.7 계산 예시 예시 Base B Visual Condition Penalty Final / 등급 1 98 DAY + 맑음 0 98 / 좋음 2 98 SUNRISE_EFFECT + 흐림 -20 78 / 양호 3 98 SUNSET_EFFECT + 비 -35 63 / 보통 4 100 NIGHT 감점 미사용 0 / 매우 나쁨 NIGHT 설명 예시: “바다 자체의 투명도는 좋지만, 밤 시간대로 자연광이 없어 실제 물속 시야 확보가 어렵습니다.” 10. Comfort C 및 Final Condition Comfort는 현재 강수량, 기온, 수온, 구름량을 사용하며 바다 자체가 좋은데 흐리다는 이유로 점수가 크게 낮아지지 않도록 한다. Comfort Modifier:  CM = 0.95 + 0.05 × (C/100) Core:  Core = 100 × (A/100)^0.63 × (B/100)^0.37 Final:  Final Score = Core × CM Comfort는 Core 바다점수를 최대 약 5%만 감점하며, 좋은 날씨라고 Core 점수를 추가 상향하지 않는다. 11. Safety / Recommendation / Condition Score 3중 분리 출력 의미 예시 Safety 절대 안전상태 PASS / BLOCK / UNKNOWN Recommendation 실제 활동 추천 추천 / 주의 / 비추천 / 야간 비추천 Condition Score 바다 컨디션 정량값 0~100 Recommendation은 Entry A를 기본으로 하되 Visibility B가 매우 낮으면 한 단계 하향한다. 예: A=90, B=35이면 추천이 아니라 주의. Comfort C는 Recommendation 등급을 변경하지 않는다. 12. Activity Time Gate - 야간·해질녘 야간은 바다 자체 컨디션을 낮추는 요소가 아니라 활동 추천을 제한하는 요소로 처리한다. 야간에도 Wave/Visibility History 계산은 계속 수행한다. Visual Visibility는 실제 물속 시각조건을 평가하고, Activity Time Gate는 입수 추천을 제한한다. NIGHT에서는 Final Visual Visibility = 0과 Recommendation = 야간 비추천이 동시에 적용되며, Base Visibility B 자체는 변경하지 않는다. 시간대 Recommendation 처리 일출 전 야간 비추천 일출 후 ~ 일몰 60분 전 정상 알고리즘 일몰 60~30분 전 해질녘 주의 일몰 30분 전 ~ 일몰 해질녘 비추천 일몰 이후 야간 비추천 예: Final 95점이라도 일몰 이후라면 ‘95점 / 야간 입수 비추천 / 바다 조건은 좋지만 일몰 후 시간대입니다.’처럼 표시한다. 야간 자체를 Hard Safety BLOCK으로 처리하지 않는다. 13. 예상 수중시야 Explain Layer 및 ‘자세히 보기’ 향후 수중시야 더보기 UI는 Base Visibility, Visual Condition, Final Visual Visibility를 다음 순서로 구분하여 표시한다. 구분 표시 내용 A. Base Visibility 파도, 너울, 파주기, 최근 강수, 지형·노출, 방파제 차폐, swell sensitivity B. Visual Condition DAY / SUNRISE_EFFECT / SUNSET_EFFECT / NIGHT, 기상상태, 시각조건 감점 C. Safety 데이터를 smoothing하거나 이전의 좋은 점수로 완화하지 않는다. Environment Profile로 Hard Safety를 해제하거나 완화하지 않는다. 강수확률을 실제 강수량과 동일한 영향값으로 사용하지 않는다. 야간이라는 이유로 Wave 또는 Base Visibility B 원시 점수를 조작하지 않는다. NIGHT의 Final Visual Visibility 0점은 별도의 시각조건 결과다. 수중시야를 실제 관측값인 것처럼 표현하지 않는다. 풍속과 파고를 중복으로 과도하게 감점하지 않는다. 16. 최종 확정 요약 모듈 최종 V1.3 원칙 Safety BLOCK/UNKNOWN/PASS 분리, BLOCK이면 점수 숨김 Wave 파고 중심 + 파주기·파향·노출·차폐·너울민감도 보정 Current 유속 기반 보수적 점수 + weakest-link Wind 현재 풍속·풍향·eastWindSensitivity만 사용, 보조 비중 Entry A Wave 60 / Current 30 / Wind 10 기하결합 + weakest-link Visibility B 최대 48h 파도·강수 이력 + 지수감쇠 + terrain 회복속도 Comfort C 현재 비·기온·수온·구름, 최대 5% 감점 Modifier Final A/B 중심 Core Score + Comfort Modifier Time Gate 일몰 전후 Recommendation만 제한, History는 계속 계산 UI Safety / Recommendation / Score 분리 + 수중시야 Explain Layer V1.3 시각조건 확정 요약 모듈 V1.3 확정 원칙 Base Visibility B V1.2 계산 구조와 등급을 그대로 보존 Visual Condition 자연광 4종 × 기상 4종, 총 16개 조합 Final Visual Visibility Base B에서 시각조건 감점 적용; NIGHT는 0점 고정 Activity Time Gate Visual Visibility와 별도로 Recommendation 제한 UI Base → Visual Condition → Final을 구분하여 설명 본 V1.3는 현재 SNORKY 2.0이 보유한 데이터로 구현 가능한 최종 설계안이다. 이후 실제 포인트 데이터와 사용자 피드백이 축적되면 계수·경계값을 조정할 수 있으나 Safety First, 실제 데이터만 사용, 수중시야 이력 기반 회복, 포인트 환경 보정, 야간 추천 분리라는 핵심 구조는 유지한다. 17. 전 화면 공통 구현 계약 본 절은 V1.3의 계산식·가중치·임계값·등급 체계를 변경하지 않고, 동일한 알고리즘 결과가 SNORKY 전체 화면에서 일관되게 사용되도록 하는 구현 규칙을 확정한다. 17.1 단일 계산 결과 원칙 동일 포인트·동일 기준시각에 대해 Safety, Recommendation, Condition Score, Visibility 결과는 공통 평가 계층에서 한 번만 산출한다. 홈, 지도, 검색, 상세 화면이 각자 점수나 상태를 다시 계산하거나 별도 임계값으로 재분류해서는 안 된다. 17.2 전 화면 동일 결과 원칙 홈의 오늘의 BEST, 내 주변 추천, 가까운 포인트, 지도 마커/선택 배너, 검색 결과, 포인트 상세는 동일한 평가 결과 객체를 공유한다. 동일 포인트·동일 시각이라면 화면이 달라도 점수, 추천 상태, 예상 수중시야 등급 및 Safety 상태가 서로 달라서는 안 된다. 17.3 Safety 사용자 노출 원칙 Safety의 PASS / BLOCK / UNKNOWN 판정은 내부적으로 모두 유지한다. 일반 사용자 요약 배너에서는 PASS 문구나 PASS 배지를 기본 노출하지 않는다. BLOCK은 '입수 금지 · 실제 차단 원인' 형태로 명확히 표시하며 Condition Score를 숨긴다. UNKNOWN은 안전정보 확인이 필요함을 표시하고 Condition Score를 숨긴다. 17.4 공통 결과 객체 최소 필드 공통 평가 결과는 최소한 safety, safetyReasons, recommendation, conditionScore, visibilityScore, visibilityGrade, visibilityExplanation, evaluatedAt 및 대표 지표 요약을 제공한다. 값이 없으면 임의의 기본값·최상값·가상값으로 채우지 않는다. 17.5 UI는 표시 계층으로 한정 각 화면은 공통 평가 결과를 화면 크기에 맞게 축약하여 표시할 수 있으나 의미를 변경해서는 안 된다. 예를 들어 지도 배너는 대표 지표 1~2개만 보여줄 수 있지만, 동일 결과를 다른 점수나 다른 컨디션으로 재해석해서는 안 된다. 17.6 시간 기준 일치 현재/시간별 화면은 평가 기준시각(evaluatedAt 또는 해당 forecast slot)을 명확히 공유한다. 서로 다른 시각의 KMA/Marine 데이터를 조합하여 같은 시각의 결과인 것처럼 표시하지 않는다. 17.7 화면별 표시 계약 화면 기본 표시 Safety 표시 금지 홈 / 추천 카드 포인트명 · Condition Score · Recommendation · Visibility 요약 PASS 숨김 / BLOCK·UNKNOWN만 명확히 표시 화면별 점수 재계산 지도 마커 / 선택 배너 점수·Recommendation·Visibility 또는 대표 지표 축약 PASS 숨김 / BLOCK 시 입수 금지 + 원인 / UNKNOWN 시 확인 필요 고정값·하드코딩 검색 결과 포인트명 · 점수 · Recommendation · Visibility 요약 PASS 숨김 / BLOCK·UNKNOWN 우선 검색용 별도 상태 분류 포인트 상세 Safety · Recommendation · Condition Score · Visibility · Explain Layer 전체 내부 상태 포함 상세 표현 가능 다른 화면과 다른 계산식 17.8 구현 우선순위 1) 공통 평가 결과 생성 계층 확정 → 2) 기존 화면별 중복 계산 제거 → 3) 동일 포인트·동일 시각 결과 일치 검증 → 4) 마지막에 카드/배너 UI 통일. 17.9 V1.3 변경 금지 본 구현 계약을 이유로 V1.3의 Safety First 원칙, Hard Safety, Wave/Current/Wind/Entry A, Visibility B, Comfort C, Final Condition, Time Gate의 수식·가중치·임계값·데이터 원칙을 임의 변경하지 않는다.
